二、计费约定（所有手算都按这里执行，并把这一节原样写进 tests/dataflow-b2b/micro/README.md）
1. 条件 C 和所有函数参数都是外部值，没有代价。
2. 原始区域 I0 也要先经过 S_loc 再计费：
   - 若原始菱形满足 Fold（两侧全部可以安全推测；两侧 c_SL 合计不超过 7，第一条操作可以单独超出；
     汇合处 PHI 不超过 3 个；i1 PHI 的入值不是二元运算），那么原始区域按“两侧都推测执行，
     每个两侧入值不同的输出用一个 select”计费，不计保护开销；
   - 否则，原始区域按“一个左保护段和一个右保护段组成的菱形”计费：控制开销 3 计一次（G2），
     每个两侧入值不同的输出计一次合流开销 1。
3. 融合方案中：
   - 共享操作和推测执行的操作，在 D、L、R 三种场景中都计费；
   - 左保护操作只在 D 和 L 计费，右保护操作只在 D 和 R 计费；
   - 每个保留下来的保护段在三种场景中都计控制开销 3，同一菱形里的左右两段只计一次；
   - 每个流出保护段、在段外被使用的值，计一次合流开销 1；
   - select 在三种场景中都计 1；i1 select 能折叠为 C 或 !C 的计 0；
   - 输出需求用 V1 或 V2 实现时没有代价。
4. 每个测试对每个列出的方案，都要写出 (T_D, T_L, T_R)，以及相对原始区域的 (Δ_D, Δ_L, Δ_R)。
