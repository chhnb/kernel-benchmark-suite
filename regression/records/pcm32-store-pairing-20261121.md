# PCM32 第 10 步的 LDS store 配对

同父候选复用 `_Z3pcmPi:B5:H6_8:H7_8`，基线为 `49697e8`。所有变体显式设置 `--region-align anchor --merge-metadata intersect`、`FUSION_TTI_COST_KIND=latency` 和 `--region-memory-pairing e0|e1|e2|e3`。只改变 Anchor 的配对报价或 E2 的兼容性和发射对齐。最终评分仍是 LLVM24 latency，产物由显式试融导出。

配对报价使用整数百分之一单位，E0 至 E3 中现有指令、普通 select、PHI 和分叉代价也同步乘以 100。E0 仅令 LDS store = 4。E1/E2 使用 LDS load/store 1.88/3.93、AS1 load/store 58.11/72.35、64 位指针 select 2.12。E3 把 load/store 改为 100，沿用 E1 其余设定。PCM32 的 AS3 指针是 32 位，2.12 的覆盖不作用于这类 LDS 指针。

E2 允许简单 load/store 在地址对齐不同的情况下配对，发射时取最小对齐。每侧的地址保证都至少达到这个值，因此降低声明对齐是安全的。减少对齐信息可能让后端拆开或放弃某些宽 LDS 指令。

## 结论

E0 的 HSACO 与原 latency Anchor 相同。把 LDS store 单独提到 4，仍得到 16 对同一步 load、零共享 store。E1 的所选方案只保留前两对 load，也没有共享 store。E0 和 E1 同时用了不同的 LDS load 报价，因此不能把形状差异归因到 store 的 4 与 3.93。

E1 的打平全配内部候选仍有 16 对 load，LLVM24 latency TTI 为 1623。打平全截候选只有 2 对 load，TTI 1609，因此显式试融导出后者。E2 的两个内部结对策略各自导出的首选都只有 2 对 load，且没有 store。选中 HSACO 与 E1 一致。段内 DP 插桩在每个策略都观察到 32 次同一步 store 转移（8 个位置，每处最多 4 个 beam 状态）。保留的次选各只有一对跨步的 store，比首选少 0.07 分。这里没有证据表明同一步的完整 load/store 对齐在允许的形状中不存在。手工 V-align 的 16 load / 8 store 形状未出现。E2 目标循环是 145 条 VALU，手工 V-align 是 193 条，两者共享访存的形状不同。历史 V-align 相对 M 的耗时比为 1.00547。

E3 的 14 对 load 与 7 对 store 与 DARM 的逐对匹配完全一致。E3 同时把 load 和 store 配对收益提到 100，结果证实强访存配对奖励能重现 DARM 的错位方案。该对照无法单独识别 store 报价的贡献，E0 则证实仅把 LDS store 提到 4 并不足以重现。

`tests/run-v1` 通过。原版 DARM 和 native latency Anchor 的 HSACO 已与上一轮逐字节核对。
