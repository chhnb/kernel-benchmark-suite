## 死代码和观测

- 删除只服务于诊断 CLI 的 `describeAnchorCondition`、`analyzeAnchorCondition` 及 LLVM 发散性说明输出。逐 wave 及条件来源分类仍由实际候选调用。
- 删除无调用的 `enumerateAdjacent`、`resolveCandidateCatalog` 和仅由旧相邻 API 触达的 `LogicalRegionState`。发布候选的参数始终传入空逻辑状态，现行 ordered 调度使用 `decision::OrderedArms`。保留实际 IR 中由活跃区域路径使用的逻辑 metadata。
- 删除无调用的 `Observer::commit`、写逻辑快照的观察器方法和虚接口。实际 Greedy 由 driver 写提交记录，结构 worker 仍写原有回执字段。
- 删除 `makeRound`／`tryPair` 中未读取的 `optLevel` 参数、未调用的 `tryPair` 重载、固定的 worker cleanup 缓存比较、固定为真的 `guardsUnsafeWork`、未读的 `Trial::insideLoop` 及未用局部集合 `oldBlocks`／`rawCreated`。已废弃的 leaf 和 replay 回执字段继续输出原来的零、空数组或空字符串。
- 删除旧 `pair_trial.cpp` 及其构建、运行包装器。其专用构建器仍引用早已移除的 `ir_dependency.cpp`，当前显式 pair 走 `fusion-search-llvm24`。删除 `prepare_current_generated.py` 的旧入口，它依赖已移除的 recursive-all32、scoped-cfg 和配对编译工具。
- 在 `b2b_anchor_observe.{h,cpp}` 集中处理 `FUSION_OBSERVE_B2B_DP` 的 JSON。DP 只传递冲突、转移、剪枝、分段和最终方案的观测值，计划与报价保持原路径。旧 JSONL 字段及格式保留。
