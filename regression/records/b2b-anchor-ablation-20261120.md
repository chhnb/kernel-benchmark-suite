实验起点为 `4a5b226`。A 是 DP1，N 是选出的 anchor。默认 B2B 保持 DP1。
11 月 19 日启动，20 日完成。GPU 沿用 v3 第 0 节固定规则。

## SRAD 诊断

### 历史第 3 次提交

在独立的诊断二进制中打印 V3 实际传给链估值的数字。两规模的数字相同，
常量下标 15、14 在 SRAD32 中分别为 31、30。

| GEP 对（左右） | c | 基指针叶子 | 三个下标及代价 | 子节点贡献 | sel_out | value + sel_out |
| --- | ---: | --- | --- | ---: | ---: | ---: |
| %158 ↔ %165 | 1 | temp ↔ east，指针按 i64 查，1 | 0↔0 为 0，0↔%13 为 1，%157↔15 为 1 | 0 | 0 | −2 |
| %156 ↔ %164 | 1 | temp ↔ temp，同一 SSA 值，0 | 0↔0 为 0，0↔%13 为 1，%155↔14 为 1 | 0 | 0 | −1 |
| %153 ↔ %161 | 1 | north ↔ temp，指针按 i64 查，1 | 0↔0 为 0，0↔%160 为 1，%12↔15 为 1 | 0 | 0 | −2 |

表中的下标值中，`%12`、`%13` 是分支前 workitem ID。
`%155`、`%157`、`%160` 分别是 `%12−1`、`%12+1`、`%13−1`，
对侧是常量，所以每对 GEP 的两个不同下标均为 i32 叶子，每个为 1。
其余下标相同。三对 GEP 都是出口 PHI 入边创建的根节点，
`sel_out=0` 由根节点规则确定，没有向 worker 查询输出 select，
也没有子节点。输入 i32 和 i64 select 均命中 LLVM 24 throughput TTI
报价 1，GEP 指令报价为 1。两个底层是 addrspace(3) 的不同基指针实际命中了
**i64** 查询，无缺省报价，故无需修正。汇合点的 load 原本只有一份，不在两臂中。

V2+P 使用 V2 的局部判定。第 3 次局部严格布局为这三个出口都计 1 点
输出 select，净值仍为 −1、0、−1，严格规则三个都截断。这个结果与 V3
所用的根节点计算口径有区别，V2+P 的同父 TTI 仍为 458。

### 历史第 1 次提交

C 单独加入时，获胜布局从 V2 的宽松、TTI 470 变为全截、TTI 480。
只加 P 时仍为宽松、470。两项合用时，全截布局在候选顺序中从第 2 变为
第 3，仍以 480 胜出。两个零值 GEP 根被全截，另一个 GEP 根为 −1。
清理后，A 的 prefix-suffix 有一条实际指针二选一。V3 有留存的
`br i1 %135` 进入 `fusion.side5`，另有两条指针／poison select 和
一条 `select i1 %135, i32 1, i32 %181` 来选择 GEP 下标。
相比 A，V3 多一条条件分支（7）、一条 GEP（1）、一条指针 select（1）
和一条 i32 select（1），全函数计数 257→261，差值正好 10 点。

## V2+P 仍比 A 差的五个同父实例

| Case／提交 | A → V2+P | 原因 |
| --- | ---: | --- |
| HLLD 2 | 1745 → 1747 | merged-exit 条件发射多一条 xor、两条 or，少一条 and，PHI 和 select 数相同 |
| Map-Airy 27 | 4301 → 4305 | 段内布局以两个标量 PHI 和两条 extractelement 替换两个向量 PHI，多发射一条双宽 fma |
| Map-Airy 30 | 4271 → 4281 | A 的 common-join-dp 下沉。N 分段发射多条件和无条件分支以及两条 select，少一条 PHI 和一条 fmul，净值 +10 |
| SRAD16 3 | 451 → 458 | 局部严格截断三个 GEP。cleanup 后少 8 条 select，但多两条分支、两条 add 和两条 GEP，净值 +7 |
| SRAD32 3 | 451 → 458 | 与 SRAD16 相同 |

原始 Greedy、试验 JSON、诊断报价和逐轮输出在 EPYC 的
`build/b2b-layouts/anchor-ablation/`。
