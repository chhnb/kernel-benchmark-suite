# 区域融合的 anchor 对齐实验

## 预先固定的推广标准

在按热循环机器码差异选出的三个同父实例中，至少两个的 anchor/DARM 耗时比的配对 bootstrap 95% 区间上限严格小于 0.98，且没有实例的区间下限严格大于 1.02。PCM32 第 10 步 R2R 单独作为额外对照，anchor 不得比 DARM 的 M 慢超过 2%。任一门槛未满足则保留 DARM，不继续实现。输出校验失败或默认 DARM 产物与发布版不一致时停止实验。

基线为 `anchor-release-20261120`。默认区域对齐为 DARM，接受规则仍由 TTI 决定。
## 原型与默认路径核验

原型提交为 `0a37fe4`。驱动与显式试融入口均支持 `--region-align darm|anchor`，默认 DARM。anchor 使用同一份块映射、复制、发射与接受规则。比较分支后继时要求对应顺序一致。跨块根使用映射块中保序对应的消费者及相同操作数位置。DARM 发射器只接受原操作数顺序，因此区域原型不启用 B2B 的可交换操作数调换。缺报价的新指令按 1 计，缺报价的标量传值按位宽计。

发布清单重建 16/16 个 IR case。最终 IR、HSACO 或 cubin 以及提交次数和最终 TTI 均与冻结清单一致，且经过 LLVM verifier。`tests/run-v1` 退出码为 0。逐用例 SHA-256 见 [发布字节核对](region-anchor-20261120/release-byte-check.json)。

## 同批 GPU 对照

在有冻结 GPU 输入的合法实例中，筛选 HSACO 不同且自然循环内机器指令编码改变的实例。按循环并集上机器指令编码序列对照中的增加和删除数（含寄存器分配或分支位移不同带来的变化）排序，同分按 case 名和提交号。只有 Map-Airy 第 24、29 次满足筛选条件。其余有 HSACO 差异的实例未观测到自然循环内编码变化。PCM32 第 10 步单独加入。Map-Airy 使用进程内、每角色每轮 3 次预热和 300 次计时的发布窗口。首次误用了单次计时窗口，相关 A/A 数据保存为试跑，不用于判定。PCM32 使用发布的 pinned-host 完整排序校验方式。完整分轮采样、A/A 重测及二进制 SHA-256 见 [GPU 明细](region-anchor-20261120/gpu-paired.json)。

## 结论

不值得推广，保留 DARM。符合条件的 2 个排名实例中，已测 2 个，95% 区间确认快超过 2% 的有 0 个，确认慢超过 2% 的有 0 个。
PCM32 第 10 步的 anchor/DARM 中位数为 1.0641。两份对照的父状态和 DARM HSACO 分别与历史 P、M 逐字节一致。anchor 使 cleanup TTI 从 1387 降至 1264，发射的其余传值 select 从 38 降至 4，热循环静态 SALU 从 145 降至 83，执行掩码操作从 96 降至 59，LDS 指令从 105 增至 112。两者都因 64 KiB LDS 限为每 CU 一个工作组。仅凭静态计数无法把性能差异归因到单一变化。

## Latency TTI 补测

复用原型提交 `0a37fe4` 与原来的同父 IR，设置 `FUSION_TTI_COST_KIND=latency`。该设置同时用于 Anchor 的指令、select、PHI 报价和合法试融之后的 TTI 选择。DARM 仍用 Smith–Waterman。未改代码和默认值。

26 次审计回放全部完成，未发生块对回退。Anchor 相对 DARM 的 cleanup TTI 更低／相同／更高为 0／13／13，HSACO 相同 13 次。已有 select 条件位的 i1 select 为 12→0，分支条件位为 57→57，其余传值 select 为 264→169。Latency 改变了 5 个审计实例的 Anchor HSACO（Map-Airy 第 24、29 次，TIGRE 第 1、2、3 次），以及额外的 PCM32 第 10 次。

PCM32 的 latency 对照代价为 1616，DARM 融合后 1665，Anchor 融合后 1623。两者仍高于父状态。主块配对数为 DARM 67、throughput Anchor 10、latency Anchor 59。latency Anchor 相对 DARM 的热循环 LDS 指令为 105→110，其中 `ds_read_b32` 50→48，`ds_write_b32` 25→32，`s_waitcnt` 53→52。两者均为 64 KiB LDS、每 CU 一个工作组。LLVM24 对这个函数报告的 LDS load 报价从吞吐量口径的 1 变为 latency 的 4，PHI 从 1 变为 0，LDS store 和 select 都保持 1，条件分支保持 7。
