固定搜索二进制 `fusion-search-llvm24` 的 SHA-256 为 `ce7ecc94a2b1c64aaf9e057ab4eaf9c01733bba9534c175e644e11303aae9f85`，`decision-greedy` 为 `fd58611658cb49d6f4c6c7c59d17c007a28e61f150efe91ebdb8a93de9025d75`，`llvm24-tti` 为 `6115d44b163ad87f564fcf6fca0e9b5b983c2139e56dd22a74bc289f5604658a`。冻结 IR 按 manifest SHA-256 校验。LUD8 取原共同父 `lud8-identical-input.6VjBaq/shared.ll`，SHA-256 为 `a52a8746779c561db1be7bc66026508f909e9eeba2223c966d7fe201435782b9`。

在每案使用相同的输出路径拼写，并对最终 IR 执行 LLVM verifier。构建设备对象沿用发布 LLVM12 O3、gfx906/ROCm 6.3.3 与两例 CUDA 的固定后端。SRAD32 沿用发布复验中各角色统一的 1024 上限运行兼容修正，静态搜索仍用冻结 IR。MapAiry 用 [共同父 IR 协议](../README.md#map-airy-共同父-ir-回归)，3 批轮换（每批 3 次预热 + 15 次）。LUD8 沿第 3 步协议，统一 ROCm 4.2.0 O3 和 `llc -O2`，固定 `-s 16384`，同批轮换各 5 次。其他输入按发布协议，按批预热至少 200 ms，A/A 使用原冻结 baseline，成对中位数在 1±1% 且跨度不超过 3%，允许立即重试一次。通过后同进程轮换 12 轮，使用配对中位数与固定种子的 10,000 次 bootstrap。A/A 两次超限时只做完整输出验证，计时不进入比较。两种 IR 逐字节相同则记别名，IR 不同但代码对象逐字节相同时也不重复计时。

常规命令在 `anchor-step4-static.py`、`anchor-step4-vllm-parallel.py`、`anchor-step4-build.py`、`anchor-step4-gpu.py` 和 `anchor-step4-lud8.py`。单提交屏蔽诊断在 `anchor-step4-ablate.py` 和 `anchor_step4_skip_worker.py`，原编译/搜索二进制保持固定。屏蔽只匹配原父状态与单个候选请求，其余搜索按原参数重放。

### NQU64 回退

G0/G1/G1+ 共用同一产物，D/L 共用同一产物。A/A 中位数 1.00005，跨度 2.84%，通过。G0/D 同批 12 轮为 **1.04886 [1.04364, 1.05543]**。第 3 次提交在 %decision.dispatch / %merged.bb16（B2:B19:B21），类型 guarded-linear，只有一侧守护，TTI **274 → 270**。移除最后一步得到的父 IR 与 D 的最终 IR **逐字节相同**，所以上述同批 D 就是静态回退产物的 GPU 对照。仅屏蔽该候选请求会改选 B2:B19:B22 的同分替代，仍产生 270，不能代表移除末次变换；该复跑仅用于核对候选替代。相应记录为 ablation/NQU64/{G0-step03,exact-last}/results.json。

统一后端后，D/G0 的 kernel 静态指令数 193/192，VGPR 10/10、SGPR 22/22、scratch 0/0，分支、global load/store 与 waitcnt 指令数量相同。差异已定位到该守护变换。现有静态证据不足以独立归因到具体流水线代价。对该案保持默认或使用 L，守护策略暂不作为全局默认。

G1 的第 2 次提交是 %149 / %276 的 guarded-linear，cleanup 对照 **662**，候选 **661**。G1 相比 G0 的整程序输出还包含其他规划差异。另在同一 G1 父状态只屏蔽这次候选，保持搬入相同并继续 Greedy，仍接受写回；最终 TTI 633。用这一回退产物和原 G1 同批复测，差约 0.16%，五次范围重叠，未观察到明确的 GPU 收益或退化。单步静态 +1 不能预测端到端的方向。

### SasPoint5 的守护收益

G0 的第 8 次提交为 %decision.dispatch1 / %255，两个单侧守护块将 TTI 从 485 降至 458。该提交的父 IR 与 L 的最终 IR 逐字节相同。interval-mixture 输入上，保留守护提交相对精确回退 L 的同批时比为 **0.93523 [0.91935, 0.93548]**。coherent-blocks 和 uniform-01 两次 A/A 均超限，两个输入的所有不同产物都通过完整输出验证。

### 完整性及异常

- 17 个 case × 五个正式配置，共 85 次正式搜索；另有 34 次 live/eager 独立归因。119 次均通过 LLVM verifier。除 LUD8 外，冻结发布集合的 21 个输入都完成完整输出验证。6 个输入可比较不同产物，5 个只有别名产物，10 个不同产物的输入因 A/A 超限只做输出验证。

## 默认值建议

- **发布默认保留 D。** 优先继续验证 L。L 已在 MapAiry 和 LUD8 缩短耗时，NQU64 与 D 同产物。HLLD、Landau 和部分其他不同产物仍缺可靠计时，当前覆盖不足以切换全部 case 的默认值。
- **守护模式保留显式开关。** LUD8 从较少守护的布局获益，但 NQU64 的具体守护提交稳定退化超过 2%。NQU64 使用 D 或 L；LUD8 可按现有输入继续采用 G0。评估新规则时把动态热路径的守护成本纳入验证。
- **建议在后续清理 eager。** 17 个 case 的 G1-eager 都与 G1 逐字节相同，G1+ 也都与只开 live 的 G1-live 逐字节相同。本轮测试范围内，eager 没有带来产物变化。
- **dedup 与 live 继续关闭。** dedup 在多个 case 改变最终产物，LUD8 的 G1/G0 以及行列更新回退补测均未观察到明确 GPU 差异。live 改变了 LUD8 和三个 SRAD 产物，SRAD 缺可靠成对计时，暂无充分依据删除或默认开启。
