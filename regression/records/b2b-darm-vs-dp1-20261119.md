# B2B DARM 与 DP1 对比 · 2026-11-19

使用 `ab2aae7` 的同一套 LLVM12 清理与 LLVM24 throughput 评分。D 显式使用 `--b2b-strategy darm`，B2R、R2B、R2R 保持默认 DARM。A 为 `4a91a50` 默认 DP1 的产物。完整 Greedy 覆盖列出的七份编译输入，vLLM 两种输入规模共用同一份编译产物，因此有八个 GPU 场景。SRAD16/32 仅用于 274 个历史候选的审计。

### 代表实例

| A 提交 | TTI A → DARM | Δselect／PHI 条数 | IR 证据与归类 |
| --- | ---: | ---: | --- |
| vLLM 7 | 5161 → 5164 | +3／0 | 同父 IR 的独立重放中，清理后唯一 TTI 差额是 3 条 select。 |
| Map-Airy 10 | 4675 → 4755 | +16／+39 | DP1 只合并末尾一对纯计算。DARM 发射前向块对齐，清理前少 25 条加减乘，却多 40 条分支、42 条 select 和 39 条 PHI。清理后算术节省 52 TTI，选择、PHI 和分支多花 132。 |
| HLLD 2 | 1745 → 1751 | 0／0 | A 用 merged-exit。DARM 原始 IR 多 23 条 select，cleanup 消去差额。最终多一条 ret、少一条无条件分支，净增 6 TTI，属于出口发射差异。 |
| HLLD 4 | 1701 → 1718 | 0／+6 | A 的 separate 布局只做清理。DARM 改写后多一条条件分支、一条无条件分支和六条 PHI，分别增加 7、4、6 TTI。 |

- vLLM 的 224 次提交候选坐标全部相同。最终 +128 TTI 精确分布在第 7、14、…、224 次提交。每次相差 3 点 select 和 1 点 fcmp，合计 +96 与 +32。32 处均属于 A 的 segment-dp 布局族。第 1 次布局发射已不同，但当轮 TTI 打平。gfx906 反汇编也显示 `v_cndmask` 376 → 568，`v_cmp*` 334 → 430，函数代码大小 11484 → 13660 字节。这些是静态计数。整链 GPU 的逐提交因果效应需要独立的稳定测量。
- TIGRE 从第 4 次提交开始分叉，最终 +2 TTI 包含条件分支 +7、select −3 和 fadd −2。HLLD 从第 2 次出口发射分叉，D 在两次提交后停下，A 之后还有 R2B 和 separate。本轮 HLLD 的 A/baseline 与 D/baseline 成对中位数分别为 1.07489 和 0.93617。此前逐次消融显示 A 的第 3 次 R2B 提交与退化同向，见 [HLLD 逐次提交回归](hlld-regression-bisect-20261119.md)。
- MS32 的首轮出口差额为 +3，PCM32 首轮布局不同，最终逐 opcode TTI 相同。
- Map-Airy 第 1 次提交即改用 DARM 块内对齐并降低当轮 TTI 45。完整 D 有更多 select（+89 TTI），算术和 intrinsic 节省更多，最终静态 TTI 比 A 低 218。各 case 的完整逐提交表位于原始数据中。

## 把 select 纳入对齐代价能补多少

当前 `tools/darm_pair_engine/RegionMelder.h` 中的 `InstrMeldingProfitabilityModel` 只按匹配指令的静态权重给分，空位罚 2。Smith–Waterman 选完对齐后，`RegionMelder.cpp` 的操作数修补才在映射值不同时发射 select。匹配权重和 cleanup 后的 LLVM24 TTI 使用不同尺度。算 select 代价时应估计映射后真正不同的操作数对，并考虑重复选择和 cleanup 可折叠的部分。

52 个较差实例合计差 305 TTI。在 37 个实例中 DARM 的最终 select TTI 较高。按直接成本估算，假设消去各实例所有超额 select TTI，其余项不变，按各自差距截断后最多补回 127 TTI（41.6%），可填平 33 个实例。在完整 vLLM 链上，同样的直接成本为 96/128（75%），另有 32 点 fcmp。这是用已观测产物估计的可归因额度。实际加罚后对齐是否变化、改选后是否消除这些指令，以及 GPU 回收多少，仍需实现后的对照检验。出口、PHI 和控制流较贵的案例不由这一项直接解释。

未修改评分器、规划器默认值或 unified 去留状态。逐候选、逐提交、代表例 IR 和逐轮校验日志位于 `build/b2b-layouts/darm-vs-dp1/`。
