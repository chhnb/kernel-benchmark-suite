# B2B DP2 同输入复验

基于 checkpoint `3510dfb`。Auto Greedy 用 `--b2b-strategy dp1|dp2` 选策略，省略该参数时使用 DP1。NQU64 两边均固定 `--b2r-strategy guarded`，以保留原来的 LDS 绕过并隔离 B2B 变化。

| Case | DP1 提交 / 最终 TTI | DP2 提交 / 最终 TTI | DP1 GPU 中位耗时 | DP2 GPU 中位耗时 |
|---|---:|---:|---:|---:|
| MS32 | 1 / 306 | 1 / 306 | 948.827 ms | 943.971 ms |
| NQU64 | 2 / 278 | 3 / 274 | 683.692 ms | 673.359 ms |

每种策略交错运行三轮。MS32 DP2 样本为 943.971、950.881、941.763 ms，和 DP1 的样本范围重叠。NQU64 DP2 三轮均更快，耗时中位数下降约 1.5%，六次运行均报告 2,279,184 个解。MS32 运行未额外做完整输出比对。

MS32 原始试融 IR 的一条加载供共享写入直接使用，同一条件驱动所有地址选择和出口传值。七个出口 PHI 携带六个不同的 SSA 值。NQU64 的第三次提交使用直接出口，只保留一段受保护的单侧工作。

DP2 每个网格位置和控制模式只保留一个标签。优点是无需 beam，代价是可能提前丢弃后续更有利的 SSA 排布。持久化动作链和 SSA 绑定沿用前序节点，避免每次转移复制整份计划。(g-A) 用于挑选前缀，完整出口经过 IR 物化、验证、清理后由 LLVM24 TTI 比较。

原始日志位于 `/data/home/chh/kernel-benchmark-suite/build/nqu-guard.WKPsAN/tail-arith.xLPf/memory-match.YIwp9c/dp2-audit.y8wx3F/`。

规划器用现有的指令估价和单位控制流／传值费用计算虚拟成本，完整试融合再调用 LLVM24 TTI。MS32 和 NQU64 的最终 DP2 IR 与上表的 GPU 计时输入一致，NQU64 只有模块标识中的日志路径不同。合成回归覆盖两种左右方向、四种出口形式、外部 PHI 前驱、CPU 返回值及内存对比和逐字节重放。
