# DARM B2B 的外部操作数 select 代价 · 2026-11-19

A 为 `4a91a50` 的默认 DP1 产物，D 为 `3623297` 记录的 DARM B2B 产物，D′ 在 `bbf1b90` 上显式使用 `--b2b-strategy darm --darm-select-cost exact`。其余融合类型继续使用原 DARM 打分。默认选择 DP1，select 代价默认 off。unified 代码和既有记录保留。七份编译输入覆盖八个 GPU 场景，vLLM 64K 与 128K 共用最终 IR。

## 打分与检查

对齐对的不同操作数只要有一侧在两臂之外，就按该位置的类型扣一笔 select 代价。分开的分支出口和单独处理的 PHI 跳过普通操作数扣分。每个位置分别扣分，重复的同一操作数对也扣，因而是保守估计。非正得分返回 0，沿用 Smith–Waterman 现有的零分配对过滤。空位扣 2，发射、unpredication 和 cleanup 沿用原实现。

报价使用已冻结到代码中的 gfx906 LLVM24 throughput 离线 select 表。`i1`、`i32`、`i64`、`float`、`double`、地址空间 0／1／3 指针为 1，`<2 x i32>` 和 `<2 x double>` 为 2。表项来自原七套离线数据库的已接受 TTI 报告。缺项使用 DataLayout 位宽，至多 32 位为 1，其余为 2。

分离用例验证两笔 64 位 fallback select 使 xor 的 3 分归零，mul 的 10 分扣至 6 仍配对。另核对了臂内操作数推迟扣分和 gfx906 的 i64 报价优先级。`tests/run-v1` 与 guarded-B2R 回归通过。显式 off 的七份完整 IR、七份 HSACO 和 274 份同父 IR 试融输出均与 D 逐字节一致。

第 7 次的 `cache_eval:B35:B37:B36` 可见两种剩余配对。两对 fcmp 保留各自不同的阈值，3.5／0.75 和 5.0／0.25，各需一条 float select。每对基础分 3，第一层扣 1，仍有 2 分。`%111 ↔ %107` 和 `%112 ↔ %108` 两对 select 各自的两个数据位置已因常量扣 2，条件位置的两侧都是臂内 fcmp，因此第一层仍给每对 1 分。实际 fcmp 对齐把左侧的 5.0 与右侧的 0.25 配对，把左侧的 3.5 与右侧的 0.75 配对。右侧的 1.25 和 1.75 两个条件留在未配对的指令中，于是这两对 select 又分别插入一条 i1 select，而且都存活于 cleanup 后，名字为 `merged.select2` 和 `merged.select5`。

若第二遍按首遍生产者映射补扣这两笔 i1 select，两个 select 配对都将降为 0。这给出了两遍对齐值得验证的具体位置。外部阈值的两个 fcmp 配对仍为 2 分，因此只补臂内生产者的代价未必能收回全部 GPU 差距。
