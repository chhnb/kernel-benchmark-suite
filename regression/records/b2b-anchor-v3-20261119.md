## 第 1 节链级截断的验收

在 `build/b2b-layouts/anchor-v3/chain-src/` 构建独立原型，保持主构建可执行文件及
默认 DP1。第一条到达的边拥有共享节点，其他边计入叶子的 select 代价以避免重复
计入收益。自底向上按给定公式估价，再自顶向下截断，净值为零时保留。
独立的定向单元测试通过，零 TTI 的 GEP 和为它产生索引的 load 都被保留，
两个输入均需 select 的 fadd 被截断。

| 同父回放 | A TTI | 链级原型 TTI | 观察 |
| --- | ---: | ---: | --- |
| vLLM 第 1 次 | 5232 | 5232 | cleanup 后与 A 逐字节一致 |
| vLLM 第 7 次 | 5161 | 5163 | 外层 select 配对及其 fcmp 子节点被截断。函数中有 75 条 select，A 有 73 条 |
| TIGRE 第 4 次 | 1017 | 1089 | 段内正向判定在 `%add494 ↔ %add508` 的 fadd 处截断。反向链另截断 17 个节点 |
| SRAD16 第 3 次 | 451 | 457 | 三对 PHI 入边 GEP 的链值为 −2、−1、−2，全部截断 |
| SRAD32 第 3 次 | 451 | 457 | 与 SRAD16 相同 |

vLLM 第 7 次中，外层 select 的两对数据输入各需 1 点 select，指令本身值 1 点。
条件 fcmp 的值为 0，扣除输出 select 后没有正贡献，因此外层 select 的链值为 −1，
相对父节点的净值为 −2。零值并入的规则不适用于这对指令。段内 PHI 计价与空对齐
只能在剩余候选上改变排序，无法恢复这对已截断的指令。两套 IR 和各 cutoff 的
数值见 `build/b2b-layouts/anchor-v3/chain-smoke/vllm-7/`。

SRAD 的候选两臂没有 load 可供沿 GEP 向上配对。四条读取通过出口 PHI 取得地址，
本来就在汇合点，回放后仍各保留一次。第三版只分享了两侧的索引加法。

vLLM 第 7 次未通过要求的字节一致验收。按停止条件，链级原型保存在独立构建目录，
分支上的规划器继续使用第二版代码。段内 PHI 计价、空对齐、留出 case 与全量第三版
验证停在这一关，默认仍为 DP1。分支的编译器和测试源码与 `f3a9394` 一致，
沿用其默认产物与 A 逐字节一致及 27 项通过、4 项已知缺件跳过的结果。
