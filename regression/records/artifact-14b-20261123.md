# 14b AMD artifact 的运行、比较与报告

起点为发布线 `630e1ed`，其 14a 普通合并提交为 `e8b6e70`。本步分支为 `artifact/run`。AMD artifact 覆盖 15 个 case、17 个计时输入。SRAD-stage2/1024 只做编译验收。SasPoint5 和 HiPIMS-George 使用 CUDA，发布冻结输入继续保留。

## 运行和编译命令

在 EPYC 的 Radeon VII（gfx906）上构建。编译后端用发布的 LLVM 12、ROCm 6.3.3 和 LUD8 的 ROCm 4.2.0。设置 `HIP_VISIBLE_DEVICES=0`、`ROCR_VISIBLE_DEVICES=0` 和实验室的 `KBS_GPU_LOCK`。原始回执、所有 sampler CSV、GPU 模块列表、A/A、命令及输出日志在 `/data/home/chh/simplify-v2/build/artifact-14b.5ZY6U4`。构建重放和发布复验的原件在 `/data/home/chh/simplify-v2/build/artifact-release.0kWt2B`。

```sh
cmake -S source/artifact -B build -DCMAKE_BUILD_TYPE=Release \
  -DLLVM_CONFIG=/data/home/chh/v2-runtime/toolchains/llvm12-jammy/usr/bin/llvm-config-12 \
  -DKBS_GPU_RUNNERS=ON
cmake --build build --parallel 12
build/kbs compare --objects "$RELEASE/artifact-verified" --out "$PWD/results"
build-no-python/kbs compare --quick --objects "$RELEASE/artifact-verified" --out "$PWD/results"
build-no-python/kbs report --out "$PWD/results"
build-no-python/kbs report --quick --out "$PWD/results"
```

复用 14a 合并后 `kbs verify` 重建的对象及各自 `build.json`。DARM-best 取冻结的原版对象，同字节角色复用样本。对外口径为 Anchor / DARM-best，补丁版的时比单独列。报告表 1 沿用 DARM Figure 7 的相对 baseline 加速比，表 3 使用 KBS 重建回执的端到端设备对象构建时间（含设备链接）。[DARM CGO'22 Figure 7 与 Table II](https://charitha22.github.io/files/cgo22.pdf)

每批同一进程载入对象并预热至少 200 ms，按窗口轮换角色，计时结果进统计前校验全部输出。完整模式每个输入 12 个窗口，先做冻结 baseline 的同对象 A/A。发布协议超限重试一次，再按 31/61 次协议递进。LUD8 从 31 次开始，用固定 pinned 缓冲区分块上传与回读。PCM32 首轮每窗口一次，采用分块 pinned 主机缓冲区。CED 和 SRAD32 用独立缓冲区的 HIP Graph，分别按原先冻结的帧数和启动配置计时。每窗口每角色取中位数，TIGRE 按六个角度批次取中位数后求和。正式时比用同窗口配对的中位数和 10,000 次 bootstrap。A/A 要求中位时比在 1±1%、比值跨度不超过 3%。快速模式为 3 个窗口，通常每窗口 11 次。vLLM、MS32、PCM32 沿用发布协议的单样本窗口。A/A 一次，区间仅供参考。

## 完整运行结果

合入 14a 后的 `kbs verify` 实测 5 分 57.482 秒，59 个对象匹配、1 个登记例外、0 个意外失败。按同 case 的四个构建回执时间求和，最长三例为 vLLM 213.18 秒、MapAiry 51.49 秒、TPACF 34.44 秒。起止墙钟时间包含整个命令，表 3 来自各 `build.json`。

完整 `kbs compare` 从首个启动到最终写出结果耗时 **48 分 56 秒**，含切换到最终 C++ 输入生成器的续跑、首次 LUD8 传输停滞及重启。各已完成输入回执的时间合计 **40 分 35.83 秒**。合计最长三例为 LUD8 1492.49 秒、vLLM 240.72 秒、TPACF 224.85 秒。所有 17 个输入都落盘，16 个完成正式计时。CED/110 的 31 次和 61 次 A/A 中位比为 1.00045、1.00994，跨度为 7.39%、3.61%，因此标记未可靠计时。进入统计的批次全部通过完整输出校验。vLLM BF 仍为登记例外。

首轮完整比较做完前五个输入后，用新二进制续跑，已写出的五份回执均被跳过。最后一个输入 LUD8 在单次 1 GiB pageable 上传中停滞约三分钟。GDB 栈显示 `hipMemcpy` 进入 HSA 的等待路径，随后恢复写样本。本轮在第六个窗口完成后结束旧进程，留下 372 个已校验样本和原始日志供诊断。这一批不进入时比。修复用一个 64 MiB pinned 缓冲区完成分块上传及回读，全部传输位于 kernel event 区间外。新批次的 744 个 A/A 样本与 1116 个正式样本均通过逐字节输出校验。A/A 中位比 0.99812，跨度 0.57%。正式批次的 Anchor、base、DARM-best 耗时中位数分别为 458.95、531.00、463.47 ms。DARM、DARM-best、BF 的 LUD8 对象同字节，复用同一时样。

初始完整比较与继续执行的 `kbs` SHA-256 分别为 `177fd0a637249b406a0fc3db5bb950627dae39896915995cebd048b2abbb27f8`、`8190c4eae9e173705a77f6e8de3fe15503c4e49e760db8f0fb9e6fc54bd1333c`。LUD8 恢复与快速模式使用 `fdf69e55b07f467c5e48afbee633d3c438c99bee03c503a35b038a0160d51fc8`，LUD8 pinned runner SHA-256 为 `b2607344f26879df28b58bcdb0e35c2d2e2e9d810cd0af18f650affff51d74bf`。完整比较各输入的 runner 和设备对象哈希见生成报告。用回执的各窗口值独立复算了 94 个配对比值中位数，全部匹配。

### 区间变化的解释

- vLLM 64K 的三个对象与历史比较逐字节相同。Anchor、DARM-best 和 base 的批次中位数分别由 2134.957、2585.756、2937.276 μs 变为 2197.756、2631.596、2973.595 μs。Anchor 的绝对时间涨幅更大，所以相对两个对照的时比均上移。两批 A/A 均合格，现有数据无法把跨批时间变化归因到某一个设备状态。128K 的历史区间与新测区间重叠。
- Landau coherent 的 Anchor 中位耗时从 22.56 μs 降至 20.96 μs，最快原版从 23.68 μs 降至 22.32 μs。14a 同批包含多个上游原版形态，14b 采用本发布的四个不同设备对象，BF 与 base 同字节。两边都比 14a 更快，Anchor 的降幅更大。本次仍复现输入依赖性，mixed 的 Anchor / base 为 0.43045，coherent 为 1.06504。
- MapAiry 的 Anchor 与最快原版的对象哈希和参考相同。与 14a 相比，两者中位耗时由 32.96、38.88 μs 变为 32.16、38.24 μs，时比差约 0.8%。HLLD 的最快原版两轮都是约 95.68 μs，Anchor 由 68.64 μs 变为 69.04 μs，时比差约 0.4%。HLLD 相对 base 慢 9.35%，落在既有 7%–15% 范围内。[已知问题](../../docs/KNOWN_ISSUES.md)
- NQU64 的旧 0.98542 区间与新 0.97934 区间相距约 0.001。单样本窗口连续两次未通过 A/A，31 次窗口后 A/A 跨度降到 0.34%。当前 Anchor 和 DARM-best 的中位耗时为 8730.153 和 8913.989 μs。第 8 步同一对象分别为 8759.104 和 8903.985 μs。更早的发布复验以归一化前的 Anchor 为分子，不能用于同对象复现判断。[归一化记录](normalize-commit-20261121.md) · [第 8 步记录](anchor-unified-dp-step8-20261122.md)
- PCM32 和 MS32 的旧 base 比值分别使用 R2R 推测修复前、归一化提交默认开启前的代码对象。新旧结果的差值需要结合对应的产物变动解读。此次 PCM32 与 Auto DARM 区间仍重叠，MS32 与第 8 步同对象区间重叠。[R2R 合并准备记录](anchor-r2r-speculation-release-20261122.md) · [第 8 步记录](anchor-unified-dp-step8-20261122.md)
- TIGRE 和 MapAiry 的旧 base 对比使用早期 Anchor 对象。15 个 case 的当期对外口径仍以 14a 登记的最快原版为对照，TIGRE 与 14a 的区间重叠。

## 快速模式与接口检查

全量快速模式耗时 **5 分 55.998 秒**。17 个输入均完成，16 个可靠计时。最长三例为 LUD8 140.84 秒、vLLM 75.06 秒、PCM32 29.95 秒。CED/110 的单次快速 A/A 中位比为 1.01237，跨度 5.55%，按设计跳过正式比较。快速区间仅供参考。[快速 Markdown](artifact-14b-20261123/quick.md) · [快速 CSV](artifact-14b-20261123/quick.csv)
