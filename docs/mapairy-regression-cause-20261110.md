# Map-Airy 5.19% 回退定位

## 结论与隔离实验

原因已定位到新增完整 SESE 叶子候选改变了贪心选择；不是前八步平衡树变化。添加这类候选的提交是 `346025c`。本轮仅在诊断副本中移除 `Inventory::leafPairs` 向候选队列插入的那一行，其余当前版本的匹配器、RegionMelder、清理、LLVM24 评分器和最终编译流程均保留。正式实现未修改。

旧版与当前的 state-0 至 state-8 除 ModuleID 外逐行相同。从共同 state-8 开始，诊断版继续提交8次（总计仍16次），恢复旧的 L1+L2 和7处内部小分支选择，并收敛。最终 GPU 二进制与冻结版本**逐字节相同**：

- 冻结版本 / 排除新候选：`affe64a238c73c36aa5704f46b50becdd2f8d4902b355536fa83745bea098422`
- 当前完整候选集合：`22f56e97be8d5c4068aa264500ad00a6ceebc372c5088198a1ed47d47813c082`

因此不需要用另一轮 GPU 噪声测量证明恢复了同一个二进制；这里没有声称重新测出了24.64 μs。24.64对25.92 μs来自上一轮同输入、同设备、三批轮换的实测。

## 第一处分歧

|---|---|---|

新候选是 `darm-complete-leaf/darm-R2B`，`replication_required=true`。左侧 E88_96 从 `cond.false7.i.i.i` 到最终 quantile join，包含整个下尾计算区域；右侧 E5_96 是上尾 `if.then.i.i.i.i` 单块，对有效概率输入对应 `0.5 < p <= 0.75`。不是下尾相邻两个普通叶子的替代编号。

它来自最初为 Hypersonic 补充的完整叶子识别能力，该能力进入通用枚举。`complete_leaf_plan=false` 与 `coalesce_gaps=false`：此次不是最新可选多锚点/前移计划、gap归并或三角清理被启用；清理仍是 scoped-cfg。新增候选原本不存在，因此不能简单解释为“旧候选的TTI权重改了”。

## 为什么静态更便宜却更慢

本次混合输入12个锚点全部小于0.5，即只运行下尾。跨上、下尾融合可以减少整个函数的静态指令成本，却无法在这些输入上节省“两边都执行”的开销；新增的路径选择和保护会影响实际执行的下尾路径。评分不使用输入分布，也未计入依赖链和寄存器压力，因此仍选择了16分的新候选。

这是与实际输入一致的机制解释。隔离实验已证明候选变化导致最终二进制变化并恢复旧版本；尚未用硬件计数器拆分每一项运行开销，不能声称全部1.28 μs只由select或寄存器导致。

## 处理建议与范围

保留冻结reference与2%门槛。不要全局删除完整叶子能力，它是Hypersonic等case所需的支持范围。应区分同一逻辑多路决策内的合并与跨层级的完整区域合并，让候选策略可显式选择；评分侧需衡量复制/单边执行新增工作，后续再验证更通用的方案。按输入特化的策略必须如实标记，不能把下尾回归数据拿来声称全输入性能更好。
